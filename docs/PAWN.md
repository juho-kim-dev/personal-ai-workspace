# PAW - Nodes · pawn

2026-10-29 사용자 확정. 공개 역할명은 **PAW - Nodes**, 약칭은 **pawn**이다. 이전 공개 제안명 PAW Notes를 대체한다. Naid는 현재 구현의 출발 제품과 기존 운영 이름이다.

## 목적과 정체성

**문서와 데이터를 연결해, 지식과 흐름을 만드는 작업공간.**

pawn은 사람과 AI가 문서와 데이터를 노드로 다루고, 그 관계를 읽고 편집하는 시각적 작업공간이다. 노트 하나에서 시작해 자료를 연결하고, 지식을 정리하고, 시스템과 작업의 흐름을 그린다. 같은 내용을 문서로 읽거나, 그래프로 탐색하거나, 캔버스에 펼쳐 생각할 수 있도록 발전시킨다.

Markdown부터 시작해 구조화 데이터와 동적 객체로 확장한다. 원문과 출처를 보존하면서 사람이 이해하기 쉬운 표현과 AI가 다루기 쉬운 구조를 함께 제공하는 것이 목표다. 확장자 자체가 AI 이해를 보장하지 않으며 명확한 스키마·참조·변경 계약이 중요하다. 이 소개는 목표를 설명하며 모든 기능의 현재 제공을 뜻하지 않는다.

## 슬로건과 소개

- 슬로건: **생각을 담고, 관계를 엮고, 흐름을 그리다.**
- 짧은 소개: **문서와 데이터를 연결해, 지식과 흐름을 만드는 작업공간.**
- 영어 소개: **A visual workspace for connecting documents and data into knowledge and flows.**

## 핵심 개념 — 개발 목표

| 요소 | 정의 |
| --- | --- |
| 노드 | 내용·속성·출처·변경 이력을 가진 대상. 첫 지원은 Markdown 문서. 문서 일부, JSON 객체, 동적 객체는 식별·수명·편집 계약을 정한 뒤 확장 |
| 관계 | 참조·근거·포함·의존·순서·입출력처럼 의미를 가진 연결. 사람이 명시한 관계, 원문에서 추출한 관계, AI가 제안한 관계를 구분 |
| 보기 | 동일한 대상과 관계를 문서·그래프·Canvas·Mermaid 등으로 표현하는 방식. 모든 보기의 무손실 양방향 변환을 일괄 약속하지 않음 |
| 작업 | 사람이 직접 또는 AI와 함께 만들기·편집·연결·검토. AI가 제안한 변경을 검토하고 관찰한 버전으로 반영 |

파일 기반 노드는 원문이 내용의 기준이다. 배치·색·확대 같은 보기 상태와 의미 관계를 구별한다. 원문 링크에서 파생한 관계와 별도로 작성한 관계의 저장 위치·동기화·충돌 규칙은 첫 단계에서 결정한다. 동적 객체의 기준 데이터와 갱신 수명은 별도 설계한다. 새 모델을 이유로 기존 파일·미지원 필드·초안·이력을 임의 변환하거나 삭제하지 않는다.

## 용도

- 마인드맵: 생각을 노드로 만들고 묶고 연결하며 구체화한다.
- PKM: 자료와 메모를 출처·주제·근거 관계로 연결하고 다시 찾는다.
- LLM Wiki: AI가 자료를 읽고 노드와 관계를 제안하며 사람이 근거와 변경을 검토한다. 자동 위키 생성 엔진이 이미 있다는 뜻은 아니다.
- 구조 시각화: 아키파이·그래피파이 같은 구조 설명·관계 탐색 용도를 지향한다. 실제 산출물 연결은 지원 형식과 실행 경계를 검증한 뒤 제공한다. 현재 통합/호환 완료를 주장하지 않는다.
- 워크플로 설계: n8n 같은 단계·조건·입출력 연결 용도를 참고한다. 흐름을 그리는 것과 실제 실행하는 것은 별개다. n8n 호환 실행기는 현재 제공하지 않는다.

## 공개 PAW 안에서의 역할

PAW Wiki는 기능하는 위키이자 독립 공개 앱들의 중앙 허브다. pawn은 자료를 펼쳐 연결하고 지식·구조·흐름을 만들어가는 작업공간이다. Wiki와 Nodes의 지식 편집 기능은 일부 겹칠 수 있으며 각자의 UI·런타임·저장소를 유지한다. 상호 링크나 미래 연계를 공유 DB나 자동 동기화 완료로 해석하지 않는다.

실제 기존 앱의 화면과 기능을 바탕으로 공개판을 준비한다. 축약된 통합 데모로 대체하지 않는다. 공개판은 확인된 보조계정의 별도 Site·저장소와 새 자료로 시작하며 개인 노트·운영 DB·첨부·인증·기존 연결은 이전하지 않는다. 공개 접근·방문자별 편집 격리·MCP 권한을 검증한 후 실제 주소를 Wiki에 연결한다.

## 현재 제공과 앞으로의 목표

2026-10-29 기준, 이 문서는 제품 방향이다. **공개 PAW - Nodes 사이트는 아직 이식·배포되지 않았다.** 현재 공개 branch의 실제 앱 준비는 Wiki이며 root 시제품의 노트 기능이나 테스트는 Nodes 인수 근거가 아니다.

| 구분 | 범위 |
| --- | --- |
| 기존 제품 main의 재사용 기반 | Markdown 편집/읽기, 파일 관리, 탭/분할, 검색/링크, 공유 초안·revision 충돌 방지·복구, Graph, Canvas, 카드 내부 노트·제목/블록 범위 편집, 기존 MCP/WebMCP |
| 기존 제품의 미병합 작업 | 고급 웹뷰어와 Canvas 선택 카드 복제. 공개판에 포함됐다고 표시하지 않음 |
| 새로 개발할 핵심 | 통합 노드 식별·의미 관계·관계 출처, 문서/Graph/Canvas 사이의 일관된 참조와 편집, AI 제안 검토 |
| 이후 확장 | 일반 JSON 구조화 보기·편집, 동적 객체, Mermaid 연동, 구조 시각화 산출물 연계, 별도 워크플로 실행 기반 |

기존 그래프의 선이 범용 의미 관계 모델을 뜻하지 않으며 Canvas JSON 편집은 일반 JSON 객체 지원과 다르다. 기존 도구 연결은 완성된 LLM Wiki 생성기나 자동 실행기를 뜻하지 않는다. 공개판의 기능·권한·브라우저 검증은 이식 시 다시 기록한다.

## 개발 목표와 완료 조건

1. **노드/관계 계약:** Markdown 문서·부분 참조의 식별, 관계 타입·방향·출처·제안 상태와 저장 방식을 정한다. 이름 변경·삭제·재접속 뒤 참조를 보존하거나 끊김을 명시하고 미지원 원문을 보존한다.
2. **첫 Markdown 흐름:** 작성 → 관계 연결 → Graph 탐색 → Canvas 배치 → 원문 편집 → 저장/복구. 동일 본문을 복제하지 않고 여러 보기에서 공유하며 배치는 관계 의미와 분리한다. 오래된 변경을 거절하고 초안을 보존한다.
3. **AI 검토:** 근거·기준 버전·변경 diff를 가진 노드/관계 제안을 승인·거절한다. 원문 관계와 AI 추론을 구분하고 거절은 원문을 바꾸지 않는다.
4. **형식 확장:** JSON 트리/표/카드와 스키마 검증, 지원 범위가 명시된 Mermaid 보기/내보내기, 동적 객체의 수명·출처를 단계적으로 검증한다. 모든 형식의 양방향 변환을 가정하지 않는다.
5. **실행 확장:** 설계한 흐름의 실행은 별도 권한·입출력·취소·재시도·중복 방지·실행 이력 검증 후 제공한다.

공개판은 기존 실제 앱의 검증된 기능부터 별도 인스턴스로 준비할 수 있다. 새 이름의 UI·독립 저장·공개 접근/방문자 격리·MCP·실제 배포 검증과 주소 기록이 필요하다. 미래 목표를 현재 기능으로 홍보하지 않는다. 기존 비공개 운영 환경은 변경하지 않는다.
